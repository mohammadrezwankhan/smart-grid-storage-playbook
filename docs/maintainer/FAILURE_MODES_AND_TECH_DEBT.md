# Failure modes and technical debt

[Handbook](../INDEX.md) · [Troubleshooting](../developer/TROUBLESHOOTING.md) · [Roadmap](../../ROADMAP.md)

These findings distinguish an implemented design limit from a demonstrated software defect. The current 153-test baseline passes. No numerical or control behavior is changed by this documentation package.

| ID | Failure or misunderstanding | Evidence and consequence | Current handling / proposed work |
|---|---|---|---|
| SG-F01 | Treating browser battery kW as sustainable native dispatch | The selected browser subtracts a fixed nonnegative contribution; native energy depends on signed MW, MWh, SOC, duration and efficiency | Document the unit/feasibility boundary; SG-R01 proposes a reproducible comparison contract |
| SG-F02 | Confusing direct engine defaults with selected lesson defaults | Engine battery default 100 kW versus lesson default 0 kW produces different direct-call results | Document both; SG-R02 proposes regression checks for configuration/engine defaults |
| SG-F03 | Assuming every stage bound survives later constraints | Temperature, energy and P–Q can override the earlier ramp target; delivered SOC is recomputed | Preserve stage results and explicit order; SG-R03 proposes owner-reviewed precedence evidence |
| SG-F04 | Calling sampled reserve margins a complete activation guarantee | Headroom is evaluated at interval starts; baseline advances separately; actual activation/recovery is absent | Label scope; SG-R06 proposes bounded exploratory activation studies |
| SG-F05 | Treating sampled envelopes as calibrated across all operation | Strict curve-shape restrictions and endpoint temperature clamping are external-data assumptions | Preserve illustrative labels; SG-R04 proposes data/provenance contracts |
| SG-F06 | Equating formatting or absolute guards with engineering uncertainty | Local tolerances and printed decimals vary by calculation | Record dimensions/guards; SG-R07 proposes scale and uncertainty evidence |
| SG-F07 | Depending on CLI human-readable text as a stable integration schema | CLI output consists of formatted text; no versioned JSON export contract is declared | Use documented Python records with explicit revision; SG-R05 evaluates serialization needs |
| SG-F08 | Assuming workflow success covers the whole handbook and browser | Link globs omit new directories; dashboard static validation does not run checkpoints/full schema | Local scoped checks and independent QA; SG-R02 proposes broader docs validation |
| SG-F09 | Rewriting all provenance pins as if they were current execution | Native catalogue, browser package and current source have distinct historical commits | Preserve history; SG-R08 proposes reproducible catalogue regeneration and deployment receipts |
| SG-F10 | Losing maintenance authority or confusing review prompts with field evidence | Source contains project checklists; current deputy/security channel/engineering approval are not established | Owner recovery and reporting guidance; SG-R09 proposes rehearsal and ownership decisions |

## Diagnose without hiding evidence

For a numerical discrepancy, retain the complete input/state/units, chosen curve CSV and priority, intermediate stage records, expected derivation and exact source SHA. Check duration conversions, sign conventions, initial SOC, loss assumptions and post-capability delivery before concluding the algorithm is wrong.

For invalid inputs, preserve the deliberate rejection rather than reducing validation to accept a desired example. Strict headers, paired option groups, sustainable baseline requirements and finite bounds are part of the contract. [models/pq_capability.py](https://github.com/mohammadrezwankhan/smart-grid-storage-playbook/blob/8bf7dd1d4cc1899dfc9fbb034f1fb3c35bd9763e/models/pq_capability.py#L510-L605) [models/frequency_watt.py](https://github.com/mohammadrezwankhan/smart-grid-storage-playbook/blob/8bf7dd1d4cc1899dfc9fbb034f1fb3c35bd9763e/models/frequency_watt.py#L186-L218) [models/reserve_headroom.py](https://github.com/mohammadrezwankhan/smart-grid-storage-playbook/blob/8bf7dd1d4cc1899dfc9fbb034f1fb3c35bd9763e/models/reserve_headroom.py#L87-L169)

For a proposed field claim, state the missing external evidence and review authority. A repository test, configured setting or completed checklist template does not establish site acceptance. [concepts/grid-code-evidence-prompt.md](https://github.com/mohammadrezwankhan/smart-grid-storage-playbook/blob/8bf7dd1d4cc1899dfc9fbb034f1fb3c35bd9763e/concepts/grid-code-evidence-prompt.md#L28-L32)

The listed proposals are planning inputs. An application change needs separate scope, scientific review, tests and approval of intended semantics. Do not “fix” an interpretation problem by silently changing units, defaults, limits, solver assumptions or historical records.
